──────── PHASE 7 — IDLE DATABASE COST CONTROL (Flag #1: Railway DBs run 24/7) ────────
Railway Postgres likely does NOT sleep — it bills continuously. At Tier 4, 20 idle apps = 20 always-on DBs draining me. Build real defenses:
- INACTIVITY DETECTION: track last-request time per app. If an app's backend gets zero traffic for N days (default 7, configurable) → mark DORMANT.
- DORMANT ACTION: snapshot/export the Postgres DB to cheap object storage (e.g. an IPFS/S3-style dump), then DELETE the live Railway DB so it stops billing. Keep the app's front-end live on IPFS.

- HARD CAP ON LIVE DBs: a configurable max number of simultaneously LIVE databases per account. Approaching it → alert me. This caps my absolute exposure no matter how many apps exist.
