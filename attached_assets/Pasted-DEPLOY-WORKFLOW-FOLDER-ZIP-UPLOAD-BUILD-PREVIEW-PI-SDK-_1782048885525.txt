══ PHASE 2 — VALIDATE & PREVIEW (stop before pinning) ══
Catch problems and let the developer SEE the site before it touches IPFS.
- IF package.json present → run the build (npm ci && npm run build).
   • Build FAILS → HALT. Show the real build error/stack trace in a red panel. Buttons: Retry / Reset. Nothing is uploaded to IPFS.

══ PHASE 4 — PIN TO IPFS (with real errors) ══
Live status: Uploading → Pinning → Sealing → Live.
- POST the deployable to Pinata with Authorization: Bearer <PINATA_JWT>.
- SUCCESS → receive the CID. Reveal: gold shield, "Sealed to the permanent web", the live URL (https://gateway.pinata.cloud/ipfs/<CID>) in a copy field, a QR code, "View live site".
- FAILURE → show the ACTUAL Pinata error (e.g. "Pinata: 401 invalid JWT", "Pinata: storage limit reached") — never a generic message. Buttons: Retry / Reset.
- Save the deployment (project, CID, size, timestamp) so Projects + Storage update.

══ PHASE 5 — CONNECT A .pi DOMAIN (auto-DNS — the paid feature) ══
Context: a developer wins a .pi domain at Pi's auction. Owning it does NOT auto-connect it — a DNS record must point the domain to their IPFS CID. The app does this for them.
1. Developer enters their .pi domain (e.g. myapp.pi) and picks which deployed project/CID it points to.
2. Verify ownership via Pi's domain/ownership API if available.
3. Create/update the DNSLink record mapping domain → CID:
   • Record: TXT  _dnslink.myapp.pi  →  dnslink=/ipfs/<CID>
   • IF Pi exposes a programmatic DNS/domain API → submit this record automatically server-side (the seamless paid feature).
   • IF Pi does NOT expose such an API yet → pre-compute the exact record and show it with one-tap "Copy record" + a deep link to Pi's domain portal, so the only manual step is pasting one pre-filled value. FLAG THIS AS "NEEDS APPROVAL" — confirm whether Pi's API supports automated DNS before building full automation.
4. On every redeploy, AUTO-UPDATE the _dnslink record to the new CID so the domain always serves the latest version.
5. SSL/HTTPS is handled by the IPFS gateway — no certificate work for the developer.
